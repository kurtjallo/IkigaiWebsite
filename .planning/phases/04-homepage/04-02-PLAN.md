    ```typescript
    import { ProblemSection } from '@/components/sections/problem'
    import { SolutionSection } from '@/components/sections/solution'
    import { PillarsGrid } from '@/components/sections/pillars-grid'

    export default function HomePage() {
      return (
        <>
          <HeroSection />
          <ProblemSection />
          <SolutionSection />
          <PillarsGrid />
          <WhoWeServe />
          <WhyIkigai />
          <CTASection />
        </>
      )
    }
    ```

    This is intentionally minimal. The page is a thin composition layer -- all logic, content, and styling lives in the section components. The root layout (from Phase 2) already wraps this with Navigation and Footer.

    After creating the file:

    1. Run `npx tsc --noEmit` to verify all imports resolve and types check
    2. Run `npm run build` to verify static export succeeds
    3. Run `npm run dev` and visually verify the homepage renders all 7 sections

    **Visual verification checklist (check in dev server):**
    - Hero: hunter-green background, large serif heading, gold "Schedule a Strategic Conversation" button
    - Problem: white background, "Strong Missions. Fragile Structures." heading, two-column layout with pain points
    - Solution: light-green background, "We Are Organizational Architects." heading, Blueprint > Build > Strengthen > Sustain flow
    - Pillars Grid: white background, 7 pillar cards in responsive grid, gold hover accents, "Learn More" links
    - Who We Serve: hunter-green background, "Built for Leaders Who Carry Mission." heading, 5 audience cards
    - Why Ikigai: light-green background, 3-column differentiators
    - CTA: black background, "Let's Architect Your Organization." heading, gold "Book Your Strategy Call" button

    **Background rhythm check:** The section backgrounds should alternate creating visual rhythm:
    hunter-green (Hero) > white (Problem) > light-green (Solution) > white (Pillars) > hunter-green (Who We Serve) > light-green (Why Ikigai) > black (CTA)

    If any section component has rendering issues, fix them in the section component files (from Plan 01), not in page.tsx. The page file should remain a clean composition.

    **Responsive check at 3 breakpoints:**
    - Desktop (1280px+): Full layouts -- 3-column pillar grid, two-column problem, 3-column why-ikigai
    - Tablet (768px): 2-column pillar grid, two-column problem, stacked or 3-column why-ikigai
    - Mobile (375px): Single column everything, hero heading smaller, stacked layouts

    Fix any responsive issues found in the section component files directly.
