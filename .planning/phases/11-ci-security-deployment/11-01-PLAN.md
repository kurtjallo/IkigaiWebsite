<task type="auto">
  <name>Task 2: Create GitHub Actions CI workflow</name>
  <files>
    .github/workflows/ci.yml
  </files>
  <action>
    Create `.github/workflows/ci.yml` with the complete CI pipeline.

    ```yaml
    name: CI

    on:
      push:
        branches: [main]
      pull_request:
        branches: [main]

    jobs:
      quality:
        name: Quality Gates
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v5

          - uses: actions/setup-node@v5
            with:
              node-version: lts/*
              cache: npm

          - name: Install dependencies
            run: npm ci

          - name: TypeScript typecheck
            run: npx tsc --noEmit

          - name: ESLint
            run: npm run lint

          - name: Build
            run: npm run build

          - name: Lighthouse CI
            uses: treosh/lighthouse-ci-action@v12
            with:
              configPath: ./lighthouserc.json
              uploadArtifacts: true
    ```

    Key decisions:

    1. **Single job, sequential steps** -- For a small static site, a single job is simpler and faster than multiple parallel jobs. Each step depends on the previous (typecheck needs install, build needs typecheck to pass, Lighthouse needs build output). Running them sequentially in one job avoids duplicating the install step.

    2. **actions/setup-node with `cache: npm`** -- This is the simplest caching approach. The setup-node action has built-in npm caching that caches `~/.npm` keyed on `package-lock.json`. No need for a separate actions/cache step.

    3. **`node-version: lts/*`** -- Uses the latest LTS version, matching what Vercel uses by default.

    4. **Trigger on push to main AND pull_request to main** -- PRs get checked before merge, pushes to main catch any post-merge issues.

    5. **`uploadArtifacts: true`** for Lighthouse -- Stores Lighthouse reports as GitHub Actions artifacts for debugging score failures.

    6. **No Playwright or axe-core in this job** -- Those are in Plan 11-02, which can run as a separate job to keep concerns separated and allow parallel execution.

    Ensure the `.github/workflows/` directory is created (mkdir -p).
