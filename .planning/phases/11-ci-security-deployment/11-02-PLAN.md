  <name>Task 1: Configure security headers in vercel.json</name>
  <files>
    vercel.json
  </files>
  <action>
    Create `vercel.json` at the project root with all security headers applied to every route.

    ```json
    {
      "$schema": "https://openapi.vercel.sh/vercel.json",
      "headers": [
        {
          "source": "/(.*)",
          "headers": [
            {
              "key": "Content-Security-Policy",
              "value": "default-src 'self'; script-src 'self' 'unsafe-inline' https://assets.calendly.com https://va.vercel-scripts.com; style-src 'self' 'unsafe-inline' https://assets.calendly.com; img-src 'self' data: https://assets.calendly.com; font-src 'self'; connect-src 'self' https://formspree.io https://vitals.vercel-insights.com https://va.vercel-scripts.com; frame-src https://calendly.com; frame-ancestors 'none'"
            },
            {
              "key": "Strict-Transport-Security",
              "value": "max-age=63072000; includeSubDomains; preload"
            },
            {
              "key": "X-Frame-Options",
              "value": "DENY"
            },
            {
              "key": "X-Content-Type-Options",
              "value": "nosniff"
            },
            {
              "key": "Referrer-Policy",
              "value": "strict-origin-when-cross-origin"
            },
            {
              "key": "Permissions-Policy",
              "value": "camera=(), microphone=(), geolocation=(), interest-cohort=()"
            }
          ]
        }
      ]
    }
    ```

    Key decisions:

    1. **CSP `'unsafe-inline'` for script-src and style-src** -- Required because Next.js static export injects inline scripts for hydration and Tailwind/Next.js emit inline styles. Nonce-based CSP requires server-side rendering which is not available with `output: 'export'`. For a static consulting website, this is an acceptable tradeoff.

    2. **CSP allowlist is minimal** -- Only the three third-party services (Calendly, Formspree, Vercel Analytics) are permitted. Everything else is blocked by `default-src 'self'`.

    3. **HSTS with preload** -- 2-year max-age with includeSubDomains. The `preload` directive means the domain can be submitted to the HSTS preload list for browsers to enforce HTTPS even on first visit.

    4. **X-Frame-Options: DENY** -- Blocks all iframe embedding of this site. Combined with CSP `frame-ancestors 'none'` for modern browsers.

    5. **Permissions-Policy disables unused features** -- Camera, microphone, geolocation, and FLoC/Topics (interest-cohort) are all disabled since a consulting website has no need for them.

    6. **X-Content-Type-Options: nosniff** -- Added as a bonus beyond SEC-01 through SEC-05. Prevents MIME type sniffing attacks.

    7. **Headers in vercel.json, NOT next.config.ts** -- The `headers` config in next.config.ts is NOT supported with `output: 'export'` (requires a Node.js server). Vercel's vercel.json `headers` property handles this at the CDN edge level.

    If a `vercel.json` already exists (from a previous phase), merge the `headers` property into it rather than overwriting the entire file.

  <action>
    Install Playwright and axe-core, create test configuration, write tests, and add Playwright to CI.

    **1. Install dependencies:**

    ```bash
    npm install -D @playwright/test @axe-core/playwright serve
    npx playwright install chromium
    ```

    - `@playwright/test` -- Playwright test runner
    - `@axe-core/playwright` -- axe accessibility testing integration
    - `serve` -- Static file server for testing against the built `out/` directory
    - Only install Chromium browser (not Firefox/WebKit) to keep CI fast

    **2. Create `playwright.config.ts`:**

    ```typescript
    import { defineConfig } from '@playwright/test';

    export default defineConfig({
      testDir: './tests',
      fullyParallel: true,
      forbidOnly: !!process.env.CI,
      retries: process.env.CI ? 2 : 0,
      workers: process.env.CI ? 1 : undefined,
      reporter: process.env.CI ? 'github' : 'html',
      use: {
        baseURL: 'http://localhost:3000',
        trace: 'on-first-retry',
      },
      webServer: {
        command: 'npx serve out -l 3000',
        port: 3000,
        reuseExistingServer: !process.env.CI,
      },
    });
    ```

    Key config choices:
    - `webServer` automatically starts `serve out` before tests -- serves the Next.js static export
    - `reporter: 'github'` in CI for inline annotations on PRs
    - Single worker in CI for stability
    - Retries in CI to handle flakiness

    **3. Create `tests/contact-form.spec.ts`:**

    ```typescript
    import { test, expect } from '@playwright/test';

    test.describe('Contact Form', () => {
      test('can fill and interact with the contact form', async ({ page }) => {
        await page.goto('/contact');

        // Verify form elements exist
        await expect(page.getByLabel(/name/i)).toBeVisible();
        await expect(page.getByLabel(/organization/i)).toBeVisible();
        await expect(page.getByLabel(/email/i)).toBeVisible();
        await expect(page.getByLabel(/challenge/i)).toBeVisible();

        // Fill form fields
        await page.getByLabel(/name/i).fill('Test User');
        await page.getByLabel(/organization/i).fill('Test Organization');
        await page.getByLabel(/email/i).fill('test@example.com');
        await page.getByLabel(/challenge/i).fill('This is a test challenge description.');

        // Verify submit button exists and is enabled
        const submitButton = page.getByRole('button', { name: /send|submit|begin/i });
        await expect(submitButton).toBeVisible();
        await expect(submitButton).toBeEnabled();

        // NOTE: We do NOT click submit -- this is a smoke test verifying the form
        // is interactive and all fields are fillable. Actually submitting would hit
        // the real Formspree endpoint, which we don't want in CI.
      });

      test('contact page renders with expected content', async ({ page }) => {
        await page.goto('/contact');

        // Verify page heading
        await expect(page.getByRole('heading', { level: 1 })).toBeVisible();

        // Verify the page has the form
        await expect(page.locator('form')).toBeVisible();
      });
    });
    ```

    Important: The smoke test fills the form but does NOT submit it. Submitting would hit the real Formspree API, which is inappropriate for CI. The test verifies that:
    - The contact page loads
    - All 4 form fields are present and interactive
    - The submit button is present and enabled
    - Fields can be filled with data

    Use accessible label selectors (`getByLabel`, `getByRole`) to also validate that the form has proper aria/label associations.

    **4. Create `tests/accessibility.spec.ts`:**

    ```typescript
    import { test, expect } from '@playwright/test';
    import AxeBuilder from '@axe-core/playwright';

    const pages = [
      { name: 'Homepage', path: '/' },
      { name: 'About', path: '/about' },
      { name: 'Services', path: '/services' },
      { name: 'Contact', path: '/contact' },
    ];

    for (const { name, path } of pages) {
      test(`${name} has no accessibility violations`, async ({ page }) => {
        await page.goto(path);

        const results = await new AxeBuilder({ page })
          .withTags(['wcag2a', 'wcag2aa'])
          .analyze();

        expect(results.violations).toEqual([]);
      });
    }
    ```

    This runs axe-core against 4 key pages with WCAG 2.1 AA rules. Each page is a separate test so failures are specific and debuggable.

    **5. Add Playwright to CI workflow (`.github/workflows/ci.yml`):**

    Add a new job after the `quality` job:

    ```yaml
      e2e:
        name: E2E & Accessibility Tests
        runs-on: ubuntu-latest
        needs: quality
        steps:
          - uses: actions/checkout@v5

          - uses: actions/setup-node@v5
            with:
              node-version: lts/*
              cache: npm

          - name: Install dependencies
            run: npm ci

          - name: Build
            run: npm run build

          - name: Install Playwright
            run: npx playwright install --with-deps chromium

          - name: Run Playwright tests
            run: npx playwright test

          - uses: actions/upload-artifact@v4
            if: ${{ !cancelled() }}
            with:
              name: playwright-report
              path: playwright-report/
              retention-days: 30
    ```

    Key decisions:
    - Separate job (`e2e`) that `needs: quality` -- only runs if typecheck/lint/build pass first
    - `--with-deps` installs system dependencies for Chromium on Ubuntu
    - Only Chromium installed (not all browsers) -- keeps CI fast (~30s install vs ~2min for all browsers)
    - Playwright report uploaded as artifact for debugging
    - Build step runs again in this job (the `out/` directory from the quality job is not shared between jobs)

    Add `playwright-report/` and `test-results/` to `.gitignore`.

    Add a script to package.json:
    ```json
    "scripts": {
      "test:e2e": "playwright test"
    }
    ```
