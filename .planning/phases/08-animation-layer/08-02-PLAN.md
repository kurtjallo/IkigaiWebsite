    Add animation wrappers to all section components across all 6 pages. The section components remain Server Components -- they import Client Component animation wrappers which handle the animation boundary.

    **Pattern: Section components import and wrap content in FadeIn/StaggerChildren. The section file itself does NOT need `'use client'` because it's just rendering a Client Component child.**

    1. **hero.tsx** -- Wrap the heading in `<FadeIn>` and the CTA button in `<FadeIn delay={0.2}>`. The hero is the first thing users see, so the staggered fade creates a cinematic entrance.

    3. **solution.tsx** -- Wrap the heading in `<FadeIn>` and the Ikigai Architecture Model intro in `<FadeIn delay={0.15}>`.

    5. **who-we-serve.tsx** -- Wrap heading in `<FadeIn>`. If audience items are in a list/grid, wrap in `<StaggerChildren>` with each item in `<StaggerItem>`.

    6. **why-ikigai.tsx** -- Wrap heading in `<FadeIn>`. Wrap the 3-column grid in `<StaggerChildren>` with each column in `<StaggerItem>`.

    7. **cta-section.tsx** -- Wrap the entire CTA content in `<FadeIn>`. Single animation for the whole block.

    **About page sections:**

    8. **founder-bio.tsx** -- Wrap heading in `<FadeIn>` and bio content in `<FadeIn delay={0.15}>`.

    9. **philosophy.tsx** -- Wrap heading in `<FadeIn>` and philosophy content in `<FadeIn delay={0.15}>`.

    10. **values-row.tsx** -- Wrap heading in `<FadeIn>`. Wrap the values icon row in `<StaggerChildren>` with each value in `<StaggerItem>`. This creates the sequential icon reveal (ANIM-02).

    12. **model-flow.tsx** -- Wrap heading in `<FadeIn>`. If the Blueprint > Build > Strengthen > Sustain phases are in a grid/list, wrap in `<StaggerChildren>` with each phase in `<StaggerItem>`.

    13. **case-study-card.tsx** -- If this component is used in a list, the parent should wrap the list in `<StaggerChildren>`.     - Do NOT add `'use client'` to section components that are currently Server Components. Importing a Client Component (FadeIn, StaggerChildren) from a Server Component is the correct pattern.

  <action>
    Add HoverAccent gold line animation to Card and Button components for ANIM-03.

    **Card component (`src/components/ui/card.tsx`):**

    The Card is currently a Server Component. To add the HoverAccent animation, there are two approaches:

    **Approach A (preferred): Make Card a Client Component.**
    Add `'use client'` to card.tsx and wrap the card content in `<HoverAccent>`. This is acceptable because Cards already have hover styling (gold border on hover from Phase 1). The HoverAccent adds the animated gold line.

    Implementation:
    - Add `'use client'` directive
    - Import `HoverAccent` from `@/components/animation/hover-accent`
    - When the `hover` prop is true (default), wrap the card's outer div in `<HoverAccent>` so the gold line appears at the bottom on hover
    - Keep all existing styling (shadow, border, padding, background)
    - The existing static `hover:border-gold/30` CSS can remain as a subtle enhancement alongside the animated gold line

    **Approach B (alternative): Create a separate AnimatedCard wrapper.**
    Keep Card as a Server Component and create a thin AnimatedCard Client Component that wraps Card in HoverAccent. This avoids making Card a Client Component but adds a wrapper layer. Use this approach if Card is used in contexts where Client Component overhead should be avoided.

    Choose Approach A -- Cards are interactive elements that benefit from being Client Components, and the added JS is minimal (HoverAccent is tiny).

    **Button component (`src/components/ui/button.tsx`):**

    Do NOT add HoverAccent to Button. Buttons already have a `transition-colors` hover effect (gold darkening). Adding an animated gold line on top would be visually cluttered. The button hover is already gold-on-gold, so an additional accent line adds no value.

    Instead, verify that the existing Button hover transitions are smooth:
    - Gold variant: `bg-gold hover:bg-gold-500` with `transition-colors duration-200`
    - Outline variant: `border-gold hover:bg-gold hover:text-black` with `transition-colors duration-200`
    - Ghost variant: `text-gold hover:underline` with `transition-colors duration-200`

    These CSS transitions are sufficient for buttons. The ANIM-03 requirement for "gold accent animations on hover for interactive elements" is satisfied by the Card's HoverAccent and the Button's existing CSS transitions.

    **Reduced motion for Card:** HoverAccent already handles reduced motion internally (from Plan 08-01). When reduced motion is active, the gold accent line renders statically without animation.
  </action>
