  <action>
    Create a 'use client' component that renders the contact form and handles submission to Formspree.

    **Form fields (4 fields max -- REQUIREMENTS say no complex multi-step forms):**
    1. Name -- text input, required
    2. Organization -- text input, optional (not all inquirers represent an org)
    3. Email -- email input, required
    4. "Tell us about your challenge" -- textarea, required, 4-6 rows

    **Honeypot anti-spam (INTG-03):**
    Add a hidden input with `name="_gotcha"`. Style it with `display: none`, set `tabIndex={-1}` and `autoComplete="off"`. Formspree silently rejects submissions where this field has a value. Do NOT use `type="hidden"` (bots know to skip those); use `type="text"` with CSS hiding.

    **Form state management:**
    Use a single `status` state: 'idle' | 'submitting' | 'success' | 'error'

    **Submission handler:**
    ```
    POST https://formspree.io/f/${process.env.NEXT_PUBLIC_FORMSPREE_ID}
    Headers: { Accept: 'application/json', Content-Type: 'application/json' }
    Body: JSON.stringify({ name, email, organization, challenge, _gotcha })
    ```

    On success (response.ok): set status to 'success'
    On error: set status to 'error'

    **Form validation:**
    Use native HTML validation (required attributes, type="email"). No need for a validation library for 4 fields. Add `noValidate` to the form element and do basic client-side checks before submission:
    - Name is not empty
    - Email matches a basic email pattern
    - Challenge description is not empty
    Show inline error messages below invalid fields.

    **UI states:**

    *idle state:* Show the form with all fields and a gold submit button. Button text: "Send Your Message" (not "Submit" -- per DSGN-11 strategic CTA language).

    *submitting state:* Disable the button, show "Sending..." text. Disable all form fields to prevent double submission.

    *success state:* Hide the entire form. Show a success message:
    - Heading (serif): "Thank You"
    - Body: "We've received your message and will respond within 2 business days."
    - A secondary note: "For immediate scheduling, you can also book a call below."
    This satisfies INTG-04 (form success confirmation with response time expectation).

    *error state:* Keep the form visible. Show an error message above the submit button: "Something went wrong. Please try again or email us directly." Include a retry note. Keep form data intact so the user doesn't have to re-enter.

    **Styling:**
    - Use design system components: import Section, SectionHeading, Container from @/components/ui
    - Form inputs: `w-full border border-neutral-300 rounded-sm px-4 py-3 text-body font-sans focus:border-gold focus:ring-1 focus:ring-gold focus:outline-none transition-colors`
    - Labels: `block text-sm font-semibold text-neutral-700 mb-2 font-sans`
    - Textarea: same as inputs but with `rows={5} resize-none`
    - Use the Button component for the submit button (variant="gold", full width on mobile)
    - Form max width: `max-w-[48rem]` (narrow container)
    - Space between fields: `space-y-6`

    **Accessibility:**
    - All inputs have associated `<label>` elements (use htmlFor + id)
    - Required fields marked with `aria-required="true"`
    - Error messages use `aria-live="polite"` and are associated with fields via `aria-describedby`
    - Submit button has clear action text, not just "Submit"
    - Honeypot field has `aria-hidden="true"` to hide from screen readers

    **Environment variable fallback:** If `NEXT_PUBLIC_FORMSPREE_ID` is not set, the form should still render but show a console warning. In production, submissions will fail gracefully with the error state.
