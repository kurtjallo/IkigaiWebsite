  <name>Task 1: Optimize images and audit JavaScript bundle</name>
  <files>

  <action>
    **1. Image Format Audit and Conversion:**

    Scan all raster images in `public/images/`:
    ```bash
    find public/images -type f \( -name "*.png" -o -name "*.jpg" -o -name "*.jpeg" \)
    ```

    For each non-WebP image found:
    - Convert to WebP format using `cwebp` (install if needed: `brew install webp`) or use an online converter
    - Target quality: 80-85% for photographs (founder photo, OG images), 90% for graphics with text
    - Keep original files as fallbacks only if needed, otherwise replace with WebP
    - Update all `<Image>` component `src` attributes to reference the `.webp` files
    - OG images (used for social sharing) should remain as PNG since not all social platforms support WebP -- keep `og-image.png` as-is

    If images are already WebP (likely if Phase 3 did this correctly), verify quality and file sizes are reasonable:
    - Photos: < 100KB each
    - Icons/graphics: < 20KB each
    - OG images: < 200KB (1200x630)

    **2. Lazy Loading Audit:**

    Review every `<Image>` component and every `<img>` tag across all pages:

    - **Above-fold images** (hero section images, logo in navigation): Must have `loading="eager"` or `priority={true}` on the Next.js Image component. These are LCP candidates -- lazy loading them would hurt LCP.
    - **Below-fold images** (case study images, testimonial avatars, about page founder photo if below fold, pillar icons if below fold): Must have `loading="lazy"` (this is the default for Next.js Image, but verify explicitly).
    - The Calendly embed loads its own assets -- nothing we can do about that, but ensure it's not blocking page render (should already be loaded via useEffect).

    **3. JavaScript Bundle Audit:**

    Run the Next.js bundle analyzer to identify large dependencies:
    ```bash
    npm run build
    ```

    Check the build output for bundle sizes. The main concerns:
    - **Framer Motion**: ~30KB gzipped. This is expected and acceptable. Verify it's only loaded on pages that use animations (it should be tree-shaken per component).
    - **Calendly script**: External, loaded async. Verify it's only on the contact page (should be, via dynamic useEffect in calendar-booking.tsx).
    - **React/Next.js runtime**: ~80-90KB gzipped. This is the baseline and cannot be reduced.
    - **No unexpected large dependencies**: Check for any library over 10KB gzipped that shouldn't be there.

    If the total JS payload exceeds 200KB gzipped (excluding Calendly), investigate:
    - Are any `'use client'` components larger than expected?
    - Is Framer Motion being imported in a way that prevents tree-shaking? (Should use `import { motion } from 'framer-motion'`, not `import * from 'framer-motion'`)
    - Are there any unused imports or dead code paths?

    **4. Font Loading Verification:**

    Verify font loading is optimized:
    - `next/font` should self-host fonts (no external Google Fonts CDN requests)
    - `display: 'swap'` should be set (prevents FOIT -- Flash of Invisible Text)
    - Check that `font-display: swap` appears in the built CSS
    - Verify no layout shift from font loading (fonts should have proper size-adjust or fallback metrics)

    **5. Static Asset Caching:**

    Since this is a static export to Vercel, verify:
    - Built JS/CSS files have content hashes in their filenames (Next.js does this automatically)
    - Images in `public/` will be served with Vercel's default cache headers
    - No unnecessary files in the `out/` directory (no .map files in production, no test files)
  </action>
